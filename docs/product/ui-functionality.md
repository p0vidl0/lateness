# Функционал веб-интерфейса

Описание составлено по коду (`backend/internal/web`, `backend/internal/domain`). Служит входом для редизайна UI. Страницы рендерит сервер, всё работает без JS; `assets/app.js` добавляет фильтры, копирование, диалоги и живые подсказки.

## Сущности

| Сущность | Что это | Ключевые поля |
|---|---|---|
| Аккаунт | Человек. Может быть администратором. | email (может отсутствовать при входе через провайдера), имя, пароль, привязанные VK ID и Telegram |
| Приглашение | Одноразовая ссылка на регистрацию, 7 дней. | пометка, админ, состояние: активно / использовано / истекло / отозвано |
| Проект | Набор ожиданий и каналов аккаунта. | название |
| Ожидание | Ритм, который должен подтверждаться. | имя, источник (сигнал или проверка), расписание, состояние, окно, дедлайн, прогон, последний `ok`, каналы |
| Проверка (probe) | Запрос, который сервис шлёт сам. | метод, URL, ожидаемый код, таймаут, время следующей проверки |
| Расписание | Интервал (период + допуск) или cron (5 полей + IANA-пояс + допуск). | kind, period, slack, cron, timezone |
| Сигнал | Входящий `POST /intake/{token}` или результат проверки. | исход `ok` / `begin` / `fail`, заметка, время |
| Смена состояния | Запись журнала переходов. | from, to, reason, at |
| Канал (outlet) | Куда слать уведомления. | SMTP: host, port, шифрование, user, password, from, to; HTTP: url; Telegram: токен бота, chat id |
| Доставка | Уведомление в канал по переходу. | в очереди / отправляется / доставлено / ошибка, попытки, последняя ошибка |

## Состояния ожидания

| Состояние | Подпись | Смысл |
|---|---|---|
| `quiet` | Ждёт сигнала | `ok` ещё не было, окно открыто |
| `on_time` | Вовремя | последний `ok` пришёл вовремя |
| `late` | Просрочено | окно закрылось, прогон истёк или пришёл `fail`; уведомление один раз |
| `held` | На паузе | оператор поставил на паузу, sweep не закрывает и не проверяет |

## Экраны

1. **Вход** `/login` — почта и пароль, кнопки «Войти через VK ID» и «Войти через Telegram» для настроенных провайдеров. Ссылки на регистрацию нет.
2. **Приглашение** `/invite/{token}` — форма регистрации или вход через провайдера; для недействительной ссылки — объяснение.
3. **Боковая панель** — переключатель проектов (`<details>`) со ссылкой «Новый проект», разделы проекта, «Профиль», «Приглашения» для администратора, аккаунт и выход.
4. **Ожидания** `/p/{project}/` — сводка по состояниям (кнопки-фильтры), чипы и поиск (на клиенте), строки: имя (с меткой «проверка»), расписание, состояние, дедлайн с прогрессом окна, прогон, последний `ok`, каналы. Сначала просроченные, удержанные в конце.
5. **Карточка** `/p/{project}/expectations/{id}` — крупный статус окна, шкала «период / допуск / просрочка», лента сигналов или проверок, смен и доставок. Для сигнала — URL приёма и `curl` для `ok`/`begin`/`fail`; для проверки — запрос и время следующей проверки. Назначенные каналы, пауза, удаление через диалог.
6. **Новое / изменить** `…/expectations/new`, `…/expectations/{id}/edit` — источник (только при создании), для проверки — метод, URL, код, таймаут; интервал или cron, готовые cron-выражения, пояс из браузера, каналы, живое описание «Как это сработает».
7. **Каналы** `/p/{project}/outlets`, `…/outlets/{id}` — список с числом назначений, редактор полей выбранного типа. Пароль и токен не показываются: пустое поле при сохранении оставляет прежнее значение. Удаление запрещено, пока канал назначен.
8. **Настройки проекта** `/p/{project}/settings` — переименование, удаление через диалог.
9. **Новый проект** `/projects/new`.
10. **Профиль** `/profile` — имя; способы входа: почта и пароль, VK ID, Telegram с кнопками «Привязать» и «Отвязать» (последний способ отвязать нельзя); смена пароля или, для аккаунта из провайдера, задание почты и пароля.
11. **Приглашения** `/admin/invites` — только администратору: создание (ссылка показывается один раз), список с состояниями, отзыв.

Время приходит в UTC и переводится в пояс браузера скриптом; без JS остаётся UTC.
