# ADR 003. Настройки outlets хранятся зашифрованными

## Решение

Настройки outlet (SMTP-сервер и пароль, URL webhook, токен Telegram-бота, chat id) лежат в `outlets.settings` одним `bytea`: JSON, запечатанный AES-256-GCM. Ключ — `LATENESS_SECRET_KEY`, base64 от 32 байт, обязателен для `serve`, `sweep` и `invite`.

- Формат: байт версии ключа, nonce, шифротекст. Версия входит в AAD. Это задел под ротацию: новый ключ получит версию 2, старые строки перешифруются фоном.
- Шифрует и расшифровывает только адаптер Postgres через `internal/secret.Cipher`. Домен и сценарии работают с открытыми структурами.
- Страницы секреты не отдают. Пустое поле пароля или токена при сохранении значит «оставить как есть» (`Outlet.KeepSecrets`).
- Ошибка Telegram не пишет токен: он вырезается из текста ошибки до журнала.

Пароли аккаунтов — bcrypt. Токены сессий и приглашений хранятся как sha256. Токен приёма хранится открыто: его URL показывается в карточке ожидания.

## Угрозы

Шифрование защищает от утечки дампа или бэкапа базы без ключа. От взлома самого процесса, у которого есть ключ, оно не защищает.

## Ротация (не реализована)

Добавить ключ версии 2 в конфиг рядом со старым, читать оба, писать новым, перешифровать строки, затем убрать старый ключ.
