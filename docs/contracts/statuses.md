# Состояния ожидания

| Состояние | Смысл |
|---|---|
| `quiet` | Сигнала `ok` (или успешной проверки) ещё не было, окно открыто. |
| `on_time` | Последнее подтверждение пришло вовремя, окно открыто заново. |
| `late` | Окно закрылось, прогон истёк или пришёл `fail`. Уведомление на переход в `late` отправляется один раз. |
| `held` | Оператор удержал ожидание. Sweep его не закрывает и не проверяет. |

Переходы, которые пишутся в журнал смен:

- `signal_ok` — из `quiet` или `late` в `on_time`: пришёл `ok` или проверка прошла.
- `signal_fail` — из `quiet` или `on_time` в `late`: задача прислала `fail`. Неудачная проверка этого перехода не делает.
- `window_closed` — sweep закрыл окно ритма: из `quiet` или `on_time` в `late`.
- `begin_expired` — sweep закрыл вооружённый прогон без `ok` в пределах допуска.
- `hold` — оператор удержал.
- `resume` — возврат. Если раньше был `ok`, состояние `on_time`, иначе `quiet`. Якорь окна ставится на текущее время, проверка запускается сразу.

Повторный `ok`, пока ожидание уже `on_time`, смену не пишет, но сдвигает дедлайн. Повторный `fail`, пока уже `late`, новое уведомление не создаёт. Переход `late` → `on_time` по `signal_ok` создаёт уведомление на каждый назначенный outlet. Если outlets не назначены, создаётся одна доставка без outlet, и она сразу падает с ошибкой «outlet is not configured» — промах виден в журнале.

Окно задаётся интервалом и допуском (`slack`) либо пятью полями cron и IANA-часовым поясом плюс тот же допуск. Плановый запуск интервала — якорь + период, cron — ближайший запуск строго после якоря в выбранном поясе. Дедлайн — плановый запуск + допуск. Окно закрыто, когда текущее время не раньше дедлайна.

Прогон после `begin` закрывается, когда текущее время не раньше `begun_at + slack`.

Источник «Проверка URL» описан в [probes.md](probes.md).
