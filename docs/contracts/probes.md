# Проверки (probes)

Ожидание с источником «Проверка URL» не ждёт сигнала: сервис сам отправляет HTTP(S)-запрос по расписанию.

## Запрос

| Поле | Значения |
|---|---|
| Метод | `GET` (по умолчанию), `HEAD`, `POST`, `PUT`, `PATCH`, `DELETE`, `OPTIONS`. Тело и заголовки не задаются. |
| URL | Только `http` и `https`, без логина и пароля в URL. |
| Ожидаемый код | Пусто — подходит любой `2xx`. Иначе — ровно этот код (100–599). |
| Таймаут | 1–60 с, по умолчанию 10 с. |

Заголовок `User-Agent: Lateness-Probe/1`. Редиректы — до 5. Тело ответа читается не больше 64 КБ и отбрасывается.

## Когда запрос уходит

- Сразу после создания, возобновления и любого сохранения ожидания.
- После успеха — в следующий плановый запуск: якорь + период или ближайший запуск cron.
- После неудачи — через `min(30 с, период)`.
- Удержанное ожидание не проверяется.

Время — с точностью до прохода sweep (`LATENESS_SWEEP_INTERVAL`).

## Как результат влияет на состояние

- Успех — сигнал `ok`: окно открывается заново, `quiet` и `late` становятся `on_time`. Возврат из `late` отправляет уведомление.
- Неудача — запись `fail` в журнале с причиной (`GET https://… → 503, 120 ms, expected 2xx`, `timeout`, ошибка соединения). Состояние не меняется.
- Если до дедлайна (плановый запуск + допуск) не было ни одного успеха, sweep закрывает окно: `late` с причиной `window_closed` и уведомление.

## Адреса

По умолчанию запросы на loopback, частные (`10/8`, `172.16/12`, `192.168/16`, `fc00::/7`), link-local (включая `169.254.169.254`) и CGNAT-адреса запрещены. Проверка идёт по фактическому IP после DNS, на каждом соединении, в том числе после редиректов. `LATENESS_PROBE_ALLOW_PRIVATE=1` снимает запрет — только для dev и e2e.
