# Приём сигнала

`POST /intake/{token}` без сессии. Токен — способность конкретного ожидания с источником «сигнал от задачи». Тело — JSON до 64 КБ.

```bash
curl -fsS -X POST https://lateness.example/intake/<token> \
  -H 'content-type: application/json' -d '{"outcome":"ok"}'
```

| Ответ | Когда |
|---|---|
| `204` | Сигнал принят. |
| `400` | Тело не разобралось: неизвестный исход, лишние поля, `note` длиннее 2000. |
| `404` | Токен неизвестен, или ожидание либо его проект удалены. |
| `409` | Ожидание менялось одновременно трижды подряд. Повторите запрос. |
| `413` | Тело больше 64 КБ. |

Тело описывает исход:

| Исход | Что происходит |
|---|---|
| `ok` | Ритм подтверждён. Состояние становится `on_time` (если ещё не было). Якорь окна и дедлайн считаются от времени приёма. Прогон после `begin` сбрасывается. Переход `late` → `on_time` создаёт исходящее уведомление. |
| `begin` | На `quiet` или `on_time` вооружает прогон: дедлайн прогона = время приёма + допуск (`slack`). Якорь окна и дедлайн ритма не меняются. Повторный `begin` сдвигает дедлайн прогона. На `late` и `held` — только журнал. |
| `fail` | Явный срыв. Если ожидание ещё не просрочено и не удержано, состояние становится `late` и создаётся одно уведомление на каждый назначенный outlet. |

```json
{"outcome": "fail", "note": "disk full"}
```

Поле `note` необязательно, до 2000 символов. Неизвестные поля отвергаются. Время сигнала берётся с часов сервера, не из тела.

Удержанное ожидание принимает сигнал в журнал и не меняет состояние.
